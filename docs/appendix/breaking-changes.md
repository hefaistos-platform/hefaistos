# Breaking Changes

## Purpose
Track notable compatibility-impacting platform changes and migration expectations.

## Audience
Operators, integrators, and maintainers upgrading between versions.

## Prerequisites
Access to release notes and deployment environment.

## Steps / Workflow
1. Review current breaking-change notices before upgrade.
2. Execute required migration actions and configuration clean-up.
3. Re-validate service health and functional coverage post-upgrade.

## Validation / Expected result
Upgrades complete without unresolved compatibility issues.

## Troubleshooting
If post-upgrade regressions occur, compare deprecated settings/formats against current support matrix.
